API / Version 2.0

The data contract.

Bounded, validated reads of computed outputs. No raw player data or database write endpoint.

OpenAPI schema ↗
Method Endpoint Purpose
GET /api/health ↗ Database/output readiness and saved model presence.
GET /api/meta ↗ Supported leagues, season coverage, defaults and model summary.
GET /api/season ↗ League-season rows; same-sample correlations. Parameters: competition, season, min_matches (5–38; default 15).
GET /api/analysis ↗ Five-season window of valid next-season changes and its own fitted line.
GET /api/clubs/{team_id} ↗ Club profile and same-competition history.
GET /api/lab/config ↗ Real five-feature club-season inputs, missingness, observed ranges and evaluation protocol.
POST /api/lab/predict Saved-model scenario inference. Finite numbers only; attacking spend cannot exceed total spend.
GET /api/export ↗ Filtered CSV export with spreadsheet-formula protection.
GET /api/project ↗ Evaluation, source-table estimates and measured infrastructure artifact.

Try a scenario.

All amounts are in euros. The returned change is a model response, not a causal spending estimate. 

curl -X POST http://localhost:8502/api/lab/predict \
  -H 'Content-Type: application/json' \
  -d '{"champagne_index":3,"total_spend":50000000,"attacking_spend":20000000,"squad_avg_age":25,"market_value_change":1000000}'

Competition IDs: IT1 (Serie A), GB1 (Premier League), ES1 (LaLiga), L1 (Bundesliga), FR1 (Ligue 1). Season format: 24/25. Invalid input returns 422; unavailable data/model returns 503. The OpenAPI JSON documents the full validation bounds.
